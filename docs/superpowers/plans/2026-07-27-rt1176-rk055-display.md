# RK055HDMIPI4MA0 MIPI-DSI Panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put an un-fakeable test pattern on the RK055HDMIPI4MA0 (720×1280, HX8394, native 2-lane MIPI-DSI) attached to the MIMXRT1170-EVKB's `J48` connector, verified in QEMU and on real silicon.

**Architecture:** Rename `RPiDisplay` → `MipiDisplay` and split it into a panel-independent `soc/` layer (LCDIFv2 + MIPI-DSI host + display clocks) and per-panel `panels/<name>/` directories selected at compile time. Add the RK055 panel config and an HX8394 driver transcribed from the BSD-3 SDK, plus a virtual HX8394 QEMU device modelled on the existing virtual TC358762. Raise `BUS_CLK_ROOT` to NXP's 240 MHz first, because this panel needs 2.4× the RPi panel's scanout bandwidth.

**Tech Stack:** C++ / Arduino-style Teensy core, CMake + ARM GCC 10, custom QEMU `mimxrt1170-evk` machine (C, GPL — firewalled), NXP MCUXpresso SDK (BSD-3) as the fact source, LinkServer + pyserial for hardware.

**Spec:** `docs/superpowers/specs/2026-07-27-rt1176-rk055-display-design.md`

## Read this before Task 1

Three things about this repo that will otherwise cost you a day:

1. **Gates are run as `./run_qemu.sh`, never `sh run_qemu.sh`.** Each gate re-execs itself under `gtimeout` via `tools/gate-lib.sh`; that only happens when the shebang runs.
2. **Silicon wins.** A QEMU pass is necessary, never sufficient. Never weaken a gate or the QEMU model to make a hardware divergence disappear — document it instead.
3. **This codebase comments heavily and explains *why*.** Every non-obvious register value carries a fact-source citation (SDK file + function, or RM section). Match that density; a bare magic number will be sent back in review.

### The register correction this plan is built on

While preparing this plan, `ANADIG_PLL_SYS_PLL{2,3}_CTRL` were re-read in
`mcuxsdk/devices/RT/RT1170/periph/PERI_ANADIG_PLL.h`:

- **`BYPASS` is bit 16** on both SYS_PLL2 and SYS_PLL3. Neither register has any field at bit 0.
- `STABLE` is bit 29, `GATE` is bit 30 (both PLLs). `POWERUP` is bit 21 on PLL3, bit 23 on PLL2.

Two consequences, both handled in Task 1:

- The claim in `cores/imxrt1176/startup.c` that "SYS_PLL3 is left BYPASSED on this board's boot
  (CTRL bit0=1)" was **a misread of the wrong bit**. In the HW-verified boot value
  `SYS_PLL3_CTRL = 0x2020201B`, bit 16 (real `BYPASS`) is **0** and bit 29 (`STABLE`) is **1** —
  SysPll3 is locked at 480 MHz before firmware runs, exactly as the OV5640 camera bring-up
  recorded. This resolves the contradiction in the spec's risk list.
- The existing guard in `startup.c` uses `const uint32_t BYPASS = 1u;` — **it tests bit 0**. It has
  worked only because bit 0 happens to read 0 on SYS_PLL2. That is a latent bug: if bit 0 ever
  read 1, the guard would silently drop the whole AHB bus to 24 MHz. Task 1 fixes it.

- [ ] **Step 2: Replace the whole step-5 block**

Replace everything from the `/* --- 5. AHB/bus CLOCK_ROOT` comment line through the closing `}` of
the braced block (i.e. up to but **not** including the `__asm__ volatile("dsb"...)` that follows)
with:

```c
	/* --- 5. AHB/bus CLOCK_ROOT — SYS_PLL3_OUT/2 = 240 MHz -------------- */
	/* BUS_CLK_ROOT (CLOCK_ROOT2) is the LCDIFv2 data-fetch clock (b_clk /
	 * apb_clk, RM 48.3.3 + AN12940 §3.3: "higher b_clk ... avoids FIFO
	 * under-run"), and the ipg_clk of the AHB peripheral bus generally.  It
	 * used to be left on the boot-ROM-safe OSC/2 source (24 MHz); that starves
	 * the LCDIFv2 scanout on silicon (RPi-7" display: persistent output-FIFO
	 * underrun, HW-verified cleared by raising it).
	 *
	 * This now matches NXP's own BOARD_BootClockRUN exactly:
	 * SYS_PLL3_OUT / 2 = 240 MHz (mcuxsdk _boards/evkbmimxrt1170/
	 * project_template/clock_config.c: kCLOCK_BUS_ClockRoot_MuxSysPll3Out = 4,
	 * .div = 2 -- and CLOCK_SetRootClock() writes DIV field = div-1, so the
	 * field value here is 1).  240 MHz is wanted because the RK055HDMIPI4MA0
	 * panel (720x1280 RGB565 @ 58.7 Hz) needs ~108 MB/s of sustained scanout,
	 * 2.4x what the 800x480 RPi panel needed.
	 *
	 * ★ An earlier revision of this comment claimed SYS_PLL3 is "left BYPASSED
	 * on this board's boot", citing CTRL bit0 = 1, and used SYS_PLL2_OUT/3 =
	 * 176 MHz instead.  That was a MISREAD OF THE WRONG BIT.  Per
	 * mcuxsdk devices/RT/RT1170/periph/PERI_ANADIG_PLL.h, SYS_PLL3_CTRL has NO
	 * field at bit 0 -- BYPASS is bit 16.  The OV5640 camera bring-up read
	 * SYS_PLL3_CTRL @ 0x40C84210 = 0x2020201B on this board at boot, in which
	 * bit 16 is 0 and bit 29 (STABLE) is 1: SysPll3 is LOCKED at 480 MHz before
	 * any firmware runs.  The same misread was baked into the guard below,
	 * which tested bit 0 as BYPASS and only worked because SYS_PLL2_CTRL bit 0
	 * happens to read 0.  Both are corrected here.
	 *
	 * Guarded three-deep so a boot that leaves a PLL down degrades instead of
	 * leaving the AHB bus dead:
	 *     SYS_PLL3_OUT / 2 = 240 MHz   preferred; NXP's value
	 *     SYS_PLL2_OUT / 3 = 176 MHz   previous value; PLL2 feeds SEMC via PFD1
	 *     OSC / 2          =  24 MHz   the old safe-slow source
	 * A PLL counts as usable when it is stable, not gated and not bypassed.
	 * SYS_PLL3_CTRL @ ANADIG 0x40C84210, SYS_PLL2_CTRL @ 0x40C84240; both use
	 * STABLE bit29, GATE bit30, BYPASS bit16 (PERI_ANADIG_PLL.h). */
	{
		volatile uint32_t *const sys_pll3_ctrl =
		    (volatile uint32_t *)0x40C84210u;
		volatile uint32_t *const sys_pll2_ctrl =
		    (volatile uint32_t *)0x40C84240u;
		const uint32_t GATE   = (1u << 30);
		const uint32_t STABLE = (1u << 29);
		const uint32_t BYPASS = (1u << 16);
		const uint32_t p3 = *sys_pll3_ctrl;
		const uint32_t p2 = *sys_pll2_ctrl;
		if (!(p3 & GATE) && !(p3 & BYPASS) && (p3 & STABLE)) {
			/* mux 4 = SYS_PLL3_OUT, DIV field 1 = divide-by-2 -> 240 MHz. */
			CCM_CLOCK_ROOT2_CONTROL = CCM_CLOCK_ROOT_CONTROL_MUX(4) |
			                          CCM_CLOCK_ROOT_CONTROL_DIV(1);
		} else if (!(p2 & GATE) && !(p2 & BYPASS) && (p2 & STABLE)) {
			/* mux 6 = SYS_PLL2_OUT, DIV field 2 = divide-by-3 -> 176 MHz. */
			CCM_CLOCK_ROOT2_CONTROL = CCM_CLOCK_ROOT_CONTROL_MUX(6) |
			                          CCM_CLOCK_ROOT_CONTROL_DIV(2);
		} else {
			/* Fallback: OSC/2 (mux 0, div 1) — the old safe-slow source. */
			CCM_CLOCK_ROOT2_CONTROL = CCM_CLOCK_ROOT_CONTROL_MUX(0) |
			                          CCM_CLOCK_ROOT_CONTROL_DIV(0);
		}
	}
```

/* panel_config.h - RK055HDMIPI4MA0 (RK055MHD091A0-CTG) panel configuration
 *
 * Copyright (c) 2026 Nicholas Newdigate
 * SPDX-License-Identifier: MIT
 *
 * 720x1280 portrait IPS, HX8394 driver IC, native 2-lane MIPI-DSI, on the
 * MIMXRT1170-EVKB's J48 40-pin FPC connector.
 *
 * Every value here is transcribed from the local BSD-3 NXP SDK; none is
 * guessed.  Fact-sources, per group:
 *   geometry + modeline   mcuxsdk _boards/evkbmimxrt1170/display_support.h
 *                         (DEMO_PANEL_RK055MHD091 -> DEMO_PANEL_WIDTH/HEIGHT)
 *                         and display_support.c (DEMO_HSW/HFP/HBP/VSW/VFP/VBP)
 *   lane count/video mode display_support.c DEMO_MIPI_DSI_LANE_NUM (2),
 *                         BOARD_SetMipiDsiConfig() videoMode = kDSI_DpiBurst,

 *                         PLL_528, div 9) and BOARD_InitMipiDsiClock()

 *   mux encodings         mcuxsdk devices/RT/RT1170/MIMXRT1176/drivers/
 *                         fsl_clock.h kCLOCK_{LCDIFV2,MIPI_ESC,MIPI_REF}_
 *                         ClockRoot_Mux*
 */
#pragma once
#include <Arduino.h>
#if defined(__IMXRT1176__)

// === Panel identity =========================================================
// Exactly one PANEL_HAS_* is defined in any build: the RT1176 has exactly one
// MIPI-DSI host, so two DSI panels can never be live at the same time.
#define PANEL_HAS_RK055 1
constexpr const char *PANEL_NAME = "RK055HDMIPI4MA0 720x1280 (HX8394)";

// === Geometry ===============================================================
constexpr uint32_t PANEL_WIDTH  = 720u;    // DEMO_PANEL_WIDTH
constexpr uint32_t PANEL_HEIGHT = 1280u;   // DEMO_PANEL_HEIGHT

// === Modeline ===============================================================
constexpr uint32_t PANEL_HSW = 6u;    // DEMO_HSW
constexpr uint32_t PANEL_HFP = 12u;   // DEMO_HFP
constexpr uint32_t PANEL_HBP = 24u;   // DEMO_HBP
constexpr uint32_t PANEL_VSW = 2u;    // DEMO_VSW
constexpr uint32_t PANEL_VFP = 16u;   // DEMO_VFP
constexpr uint32_t PANEL_VBP = 14u;   // DEMO_VBP

constexpr uint32_t PANEL_HTOTAL = PANEL_WIDTH  + PANEL_HFP + PANEL_HSW + PANEL_HBP;
constexpr uint32_t PANEL_VTOTAL = PANEL_HEIGHT + PANEL_VFP + PANEL_VSW + PANEL_VBP;
static_assert(PANEL_HTOTAL == 762u,  "htotal must stay 720+12+6+24 = 762");
static_assert(PANEL_VTOTAL == 1312u, "vtotal must stay 1280+16+2+14 = 1312");

// === Framebuffer ============================================================
constexpr uint32_t PANEL_BYTES_PER_PIXEL = 2u;   // RGB565 -- v1's only format
constexpr uint32_t PANEL_PITCH_BYTES = PANEL_WIDTH * PANEL_BYTES_PER_PIXEL;    // 1440
constexpr uint32_t PANEL_FB_BYTES    = PANEL_PITCH_BYTES * PANEL_HEIGHT;       // 1,843,200

// The framebuffer lives in SDRAM (extmem_malloc); 1.8 MB will not fit in OCRAM.
// 1440 is already a multiple of 32, so the SDK's FRAME_BUFFER_ALIGN of 32 costs
// no padding -- which the flat FB_SUM walk in the gate depends on.
static_assert(PANEL_PITCH_BYTES % 32u == 0u,
              "pitch must be 32-byte aligned so the scanout stride needs no padding");

// === Register-field headroom ================================================
// Same checks display_timing.h applies for the RPi panel, re-derived here for
// the larger geometry -- 1280 is the value most likely to overflow something.
// LCDIFv2 DISP_SIZE DELTA_X/DELTA_Y and CTRLDESCL1 WIDTH/HEIGHT are 12-bit.
static_assert(PANEL_WIDTH <= 0xFFFu && PANEL_HEIGHT <= 0xFFFu,
              "LCDIFv2 DISP_SIZE/CTRLDESCL1 geometry fields are 12-bit");
// LCDIFv2 blanking fields are 9-bit.
static_assert(PANEL_HFP <= 0x1FFu && PANEL_HSW <= 0x1FFu && PANEL_HBP <= 0x1FFu,
              "LCDIFv2 horizontal blanking fields are 9-bit");
static_assert(PANEL_VFP <= 0x1FFu && PANEL_VSW <= 0x1FFu && PANEL_VBP <= 0x1FFu,
              "LCDIFv2 vertical blanking fields are 9-bit");
// MIPI-DSI DPI VBP/VFP are 8-bit; VACTIVE is 14-bit.
static_assert(PANEL_VFP <= 0xFFu && PANEL_VBP <= 0xFFu,
              "DSI DPI VFP/VBP are 8-bit");
static_assert(PANEL_HEIGHT <= 0x3FFFu, "DSI DPI VACTIVE is 14-bit");
// CTRLDESCL3[PITCH] is 16-bit.
static_assert(PANEL_PITCH_BYTES <= 0xFFFFu, "CTRLDESCL3[PITCH] is 16-bit");

// === DSI link parameters ====================================================
// Two data lanes (DEMO_MIPI_DSI_LANE_NUM = 2 for every non-RPi panel).
constexpr uint32_t PANEL_DSI_LANES = 2u;
// BURST mode, unlike the RPi panel's non-burst-with-sync-pulse.  Burst lets the
// line go out faster than pixel rate and idle in LP, which relaxes the HS link
// timing; it is what NXP uses for this panel and is NOT interchangeable.
constexpr uint32_t PANEL_DSI_VIDEO_MODE = 2u;      // kDSI_DpiBurst
// EoTp on, also unlike the RPi panel.  Easy to miss; a mismatch here shows up
// as a blank panel with no diagnostic.
constexpr bool     PANEL_DSI_AUTO_EOTP  = true;

// === Clock plan =============================================================
// No VIDEO_PLL.  NXP sources both the pixel and escape clocks from PLL_528
// (SYS_PLL2), which the boot ROM already has locked -- so this panel skips the
// ANATOP AI-protocol PLL bring-up the RPi panel needs entirely.
#define PANEL_NEEDS_VIDEO_PLL 0
constexpr uint32_t PANEL_ROOT70_LCDIFV2_MUX  = 4u;  // SysPll2Out (528 MHz)
constexpr uint32_t PANEL_ROOT71_MIPI_REF_MUX = 1u;  // Osc24MOut
constexpr uint32_t PANEL_ROOT72_MIPI_ESC_MUX = 4u;  // SysPll2Out

constexpr uint32_t PANEL_SYS_PLL2_HZ = 528000000u;
constexpr uint32_t PANEL_ROOT70_LCDIFV2_DIV  = 9u;   // 528/9  = 58.667 MHz pixel
constexpr uint32_t PANEL_ROOT71_MIPI_REF_DIV = 1u;   // 24 MHz D-PHY reference
constexpr uint32_t PANEL_ROOT72_MIPI_ESC_DIV = 11u;  // 528/11 = 48 MHz escape

// The pixel clock, and the frame rate it produces on this modeline.
constexpr uint32_t PANEL_PIXEL_CLK_HZ = PANEL_SYS_PLL2_HZ / PANEL_ROOT70_LCDIFV2_DIV;
static_assert(PANEL_PIXEL_CLK_HZ == 58666666u,
              "528 MHz / 9 = 58,666,666 Hz (integer division)");
// 58,666,666 / (762 * 1312) = 58.68 Hz.  Not 60: NXP's divider choice trades
// exact 60 Hz for an integer divide off a PLL that is already up.  Recorded
// here so nobody "fixes" it later thinking it is a mistake.
constexpr uint32_t PANEL_REFRESH_MHZ_X1000 =
    (uint32_t)(((uint64_t)PANEL_PIXEL_CLK_HZ * 1000u) / (PANEL_HTOTAL * PANEL_VTOTAL));
static_assert(PANEL_REFRESH_MHZ_X1000 > 58000u && PANEL_REFRESH_MHZ_X1000 < 59000u,
              "this modeline + divider should land at ~58.7 Hz");

#else
#error "panel_config targets the i.MX RT1176 (__IMXRT1176__)"
#endif
```

#ifndef HW_DISPLAY_IMXRT_HX8394_H
#define HW_DISPLAY_IMXRT_HX8394_H

#include "hw/core/sysbus.h"
#include "hw/display/imxrt_lcdifv2.h"
#include "hw/display/imxrt_mipi_dsi.h"
#include "qom/object.h"
#include "qemu/units.h"

#define TYPE_IMXRT_HX8394 "imxrt.hx8394"
OBJECT_DECLARE_SIMPLE_TYPE(IMXRTHx8394State, IMXRT_HX8394)

/*
 * ---------------------------------------------------------------------------
 * THE REQUIRED-INIT CONTRACT
 * ---------------------------------------------------------------------------
 *
 * Unlike the Raspberry Pi panel there is no bridge chip here: the HX8394 IS the
 * panel driver, and it is configured by DSI GENERIC LONG WRITEs (data type
 * 0x29) and GENERIC SHORT WRITEs whose first payload byte is the command
 * opcode.  There is no register address to decode - the opcode is the first
 * byte, and everything after it is that command's parameters.
 *
 * That makes a MUCH tighter contract possible than the TC358762's region-based
 * one, because the sequence is published in a permissively-licensed source
 * (mcuxsdk components/video/display/hx8394/fsl_hx8394.c, BSD-3) and the
 * firmware transcribes exactly it.  Four conditions:
 *
 *   1. EXTC UNLOCK FIRST - the very first command must be 0xB9 with payload
 *      FF 83 94.  The HX8394 ignores every manufacturer command until this
 *      "SETEXTC" unlock arrives; a sequence that sends anything else first is
 *      talking to a chip that is not listening.  This is the single most
 *      likely real-world mis-ordering and it is silent on hardware.
 *
 *   2. SETMIPI LANE COUNT AGREES WITH THE HOST - a 0xBA command must arrive,
 *      and its first parameter's low two bits must equal the DSI host's
 *      CFG_NUM_LANES.  fsl_hx8394.c builds this byte as 0x60 | (dsiLanes - 1),
 *      and CFG_NUM_LANES holds lanes-1, so the two encode the same number.
 *      ★ This is the assertion that most justifies the model existing: on real
 *      silicon, telling the panel one lane count while the host drives another
 *      produces a blank screen with no error anywhere.  QEMU can catch it for
 *      free, so it does.
 *
 *   3. SLEEP-OUT BEFORE DISPLAY-ON - DCS 0x11 (exit_sleep_mode) must arrive
 *      before DCS 0x29 (set_display_on).  Reversed, the panel never leaves
 *      sleep and shows nothing.
 *
 *   4. STARTED - DCS 0x29 (set_display_on) arrived.  Until it does, the panel
 *      is configured but dark, which is a distinct failure from "misconfigured"
 *      and gets its own status bit so a failing gate says which.
 *
 * NOT required (deliberately): the 21 tuning commands between SETMIPI and
 * sleep-out.  Their VALUES are panel-calibration data (gamma, power, gate
 * timing) that this model has no way to judge, and requiring specific literals
 * would make the gate demand whatever this file guessed instead of what the
 * firmware transcribed.  They are COUNTED (see ST_CMD_COUNT) so "did the table
 * actually get sent?" is answerable, but never inspected.
 *
 * FOR THE FIRMWARE TASK (Task 12): send the real fsl_hx8394.c sequence.  Do NOT
 * trim it to this model's minimum and do NOT add commands to satisfy this
 * model.  If a faithfully transcribed sequence ever fails these checks, the
 * SEQUENCE is the fact and THIS FILE is what changes - record the divergence.
 * Silicon remains the final oracle: this model proves the bring-up is
 * well-formed and correctly ordered, never that the real HX8394 locks.
 */

/* DSI data types this model decodes. */
#define HX8394_DT_GENERIC_LONG_WRITE     0x29
#define HX8394_DT_GENERIC_SHORT_WRITE_1  0x13
#define HX8394_DT_GENERIC_SHORT_WRITE_2  0x23
#define HX8394_DT_DCS_SHORT_WRITE_0      0x05

/* Commands the contract keys on. */
#define HX8394_CMD_SETEXTC               0xB9  /* payload FF 83 94 = unlock   */
#define HX8394_CMD_SETMIPI               0xBA  /* param0 = 0x60 | (lanes-1)   */
#define HX8394_DCS_EXIT_SLEEP_MODE       0x11
#define HX8394_DCS_SET_DISPLAY_ON        0x29

/* SETEXTC's three magic payload bytes. */
#define HX8394_SETEXTC_P0                0xFF
#define HX8394_SETEXTC_P1                0x83
#define HX8394_SETEXTC_P2                0x94

/* SETMIPI param0: the lane count lives in the low two bits. */
#define HX8394_SETMIPI_LANE_MASK         0x03

/*
 * ---------------------------------------------------------------------------
 * QEMU-ONLY DEBUG TAP - no hardware counterpart
 * ---------------------------------------------------------------------------
 *
 * Identical rationale to the TC358762 tap: the real panel has no registers in
 * the SoC address map, so this window is emulator fiction and is the PANEL_SUM
 * oracle.  It is mapped over the RESERVED upper part of the MIPI DSI host's own
 * 16 KiB AIPS slot so that on silicon the firmware's read returns 0 rather than
 * faulting, and TAP_ID reading 0 is how the gate distinguishes "no tap here"
 * (hardware) from "tap says the panel is dark" (a real failure).
 *
 * It uses a DIFFERENT base from the TC358762 tap so both models can be built
 * into one binary without overlapping; only one is instantiated per machine.
 *
 * Nothing in the firmware may depend on these values on hardware.
 */
#define IMXRT_HX8394_TAP_BASE            0x4080E000
#define IMXRT_HX8394_MMIO_SIZE           (4 * KiB)

#define HX8394_TAP_ID                    0x00  /* magic; 0 on real silicon    */
#define HX8394_TAP_STATUS                0x04  /* readiness + diagnostics     */
#define HX8394_TAP_PANEL_SUM             0x08  /* checksum, or the sentinel   */
#define HX8394_TAP_LAST_CMD              0x0C  /* last decoded command opcode */
#define HX8394_TAP_LANES                 0x10  /* lanes the panel was told    */

/* TAP_ID magic ("HX94"): present only under QEMU. */
#define HX8394_TAP_ID_MAGIC              0x48583934

/*
 * PANEL_SUM sentinel: returned whenever no pixels reached the panel, i.e. the
 * panel is not ready OR the LCDIFv2 layer feeding it is not enabled.  Same
 * value and same reasoning as the TC358762 model - 0 is also what
 * imxrt_lcdifv2_scan_checksum() returns when there is nothing to scan, so
 * "0 means no valid frame" is one consistent rule across both models, and the
 * sentinel is always a DECISION (the panel refused) rather than an inference
 * from the number.  Firmware distinguishes "no tap" from "dark" via TAP_ID and
 * TAP_STATUS, never by testing this word against 0.
 */
#define HX8394_PANEL_SUM_INVALID         0

/* TAP_STATUS bits. */
#define HX8394_ST_INIT_COMPLETE      (1u << 0)  /* contract 1-4 satisfied     */
#define HX8394_ST_DSI_READY          (1u << 1)  /* imxrt_mipi_dsi_ready()     */
#define HX8394_ST_READY              (1u << 2)  /* all of the above -> lit    */
/* Init sub-conditions, so a failing gate says WHICH part of the contract. */
#define HX8394_ST_EXTC_FIRST         (1u << 4)  /* contract 1                 */
#define HX8394_ST_LANES_MATCH        (1u << 5)  /* contract 2                 */
#define HX8394_ST_SLEEP_OUT_ORDER    (1u << 6)  /* contract 3                 */
#define HX8394_ST_DISPLAY_ON         (1u << 7)  /* contract 4                 */
/* Saturating counters, so "did anything arrive at all?" is answerable. */
#define HX8394_ST_CMD_COUNT_SHIFT    8          /* [15:8]  commands decoded   */
#define HX8394_ST_PACKET_COUNT_SHIFT 16         /* [23:16] DSI packets        */
#define HX8394_ST_COUNT_MAX          0xFFu
/*
 * Scanout condition, orthogonal to the panel FSM: the LCDIFv2 layer feeding the
 * panel is actually enabled (CTRLDESCL5[EN]).  A bring-up can satisfy the whole
 * init contract and still show nothing by never enabling the layer, so this
 * gates PANEL_SUM too - and its own bit makes that say "layer not enabled"
 * rather than just "no valid frame".
 */
#define HX8394_ST_LAYER_ENABLED      (1u << 24)

struct IMXRTHx8394State {
    /*< private >*/
    SysBusDevice parent_obj;

    /*< public >*/
    MemoryRegion iomem;

    /* Readiness FSM output: false until the whole contract is satisfied. */
    bool ready;

    /* Required-init tracking (see the contract above). */
    uint32_t commands;          /* commands decoded (sequence number)         */
    uint32_t packets;           /* DSI packets received, of any type          */
    bool extc_first;            /* contract 1: SETEXTC was command #1         */
    bool lanes_match;           /* contract 2: SETMIPI agreed with the host   */
    bool sleep_out;             /* DCS 0x11 seen                              */
    bool sleep_out_before_on;   /* contract 3                                 */
    bool display_on;            /* contract 4                                 */
    uint8_t last_cmd;           /* diagnostics                                */
    uint8_t told_lanes;         /* lanes-1 as decoded from SETMIPI            */

    /* Links, resolved as QOM properties by the machine. */
    IMXRTMipiDsiState *dsi;
    IMXRTLcdifv2State *lcdifv2;
};

#endif /* HW_DISPLAY_IMXRT_HX8394_H */
```

```c
/* Decode one DSI packet into a panel command.  The opcode is payload[0]; the
 * remaining bytes are that command's parameters.  Short packets carry their
 * parameter count in the data type, NOT in len (which is always 2) -- reading
 * len as a count is the classic bug this comment exists to prevent. */
static void hx8394_packet(IMXRTMipiDsiPacketSink *sink, uint8_t vc,
                          uint8_t dt, const uint8_t *payload, uint32_t len)
{
    IMXRTHx8394State *s = IMXRT_HX8394(sink);
    uint32_t params;

    s->packets = hx8394_sat_inc(s->packets);

    switch (dt) {
    case HX8394_DT_DCS_SHORT_WRITE_0:
    case HX8394_DT_GENERIC_SHORT_WRITE_1:
        params = 0;
        break;
    case HX8394_DT_GENERIC_SHORT_WRITE_2:
        params = 1;
        break;
    case HX8394_DT_GENERIC_LONG_WRITE:
        if (len < 1) {
            return;
        }
        params = len - 1;
        break;
    default:
        return;   /* not a command channel this panel listens on */
    }

    s->commands = hx8394_sat_inc(s->commands);
    s->last_cmd = payload[0];

    /* Contract 1: SETEXTC FF 83 94 must be the very first command. */
    if (s->commands == 1) {
        s->extc_first = (payload[0] == HX8394_CMD_SETEXTC && params >= 3 &&
                         payload[1] == HX8394_SETEXTC_P0 &&
                         payload[2] == HX8394_SETEXTC_P1 &&
                         payload[3] == HX8394_SETEXTC_P2);
    }

    /* Contract 2: SETMIPI's lane field must agree with the DSI host. */
    if (payload[0] == HX8394_CMD_SETMIPI && params >= 1) {
        s->told_lanes = payload[1] & HX8394_SETMIPI_LANE_MASK;
        s->lanes_match = (s->told_lanes == imxrt_mipi_dsi_num_lanes(s->dsi));
    }

    /* Contracts 3 and 4: sleep-out then display-on, in that order. */
    if (payload[0] == HX8394_DCS_EXIT_SLEEP_MODE && params == 0) {
        s->sleep_out = true;
    }
    if (payload[0] == HX8394_DCS_SET_DISPLAY_ON && params == 0) {
        s->display_on = true;
        s->sleep_out_before_on = s->sleep_out;
    }

    hx8394_update_ready(s);
}
```

`hx8394_sat_inc()` is the saturating counter helper — copy `tc358762_sat_inc()` from the reference
file verbatim (it clamps at `HX8394_ST_COUNT_MAX` so a runaway packet stream cannot wrap a status
field back to a plausible-looking small number).

The readiness helpers:

```c
static bool hx8394_init_complete(IMXRTHx8394State *s)
{
    return s->extc_first && s->lanes_match &&
           s->sleep_out_before_on && s->display_on;
}

static void hx8394_update_ready(IMXRTHx8394State *s)
{
    s->ready = hx8394_init_complete(s) && imxrt_mipi_dsi_ready(s->dsi);
    imxrt_lcdifv2_set_downstream_ready(s->lcdifv2, s->ready);
}
```

The MMIO read handler returns `HX8394_TAP_ID_MAGIC` for `TAP_ID`, the assembled status word for
`TAP_STATUS`, `imxrt_lcdifv2_scan_checksum(s->lcdifv2)` for `TAP_PANEL_SUM` when
`s->ready && layer enabled` and `HX8394_PANEL_SUM_INVALID` otherwise, `s->last_cmd` and
`s->told_lanes` for the last two. Writes are ignored. Reset clears every tracking field.

`imxrt_mipi_dsi_num_lanes()` may not exist yet — check `include/hw/display/imxrt_mipi_dsi.h` and
add a one-line accessor returning `CFG_NUM_LANES + 1`'s stored field if it is missing. Match the
existing `imxrt_mipi_dsi_ready()` accessor's style.

Every address below is transcribed from
`mcuxsdk/devices/RT/RT1170/MIMXRT1176/drivers/fsl_iomuxc.h` (the `IOMUXC_<pad>_<gpio>` macros,
whose expansion is `muxRegister, muxMode, inputRegister, inputDaisy, configRegister`) and the
GPIO bases the OV5640 camera bring-up HW-verified:

| Signal | GPIO | Pad | MUX reg | ALT | PAD cfg reg |
|---|---|---|---|---|---|
| Panel reset | `GPIO9_IO01` | `GPIO_AD_02` | `0x400E8114` | `0xA` | `0x400E8358` |
| Backlight | `GPIO9_IO29` | `GPIO_AD_30` | `0x400E8184` | `0xA` | `0x400E83C8` |
| Panel power | `GPIO11_IO16` | `GPIO_DISP_B2_15` | `0x400E8250` | `0xA` | `0x400E8494` |

GPIO bases: `GPIO9` = `0x40C64000`, `GPIO11` = `0x40C6C000`. Register offsets within each:
`DR` `+0x00`, `GDIR` `+0x04`, `DR_SET` `+0x84`, `DR_CLEAR` `+0x88`.

`panelGpioBegin()` writes `0xA` to each mux register (plain ALT10, no SION — these are outputs and
nothing reads them back through the pad), sets the three `GDIR` bits, drives all three low, and
returns false if any `GDIR` bit does not read back set. A silent pin failure here presents
identically to a dead panel later, which is why it is checked rather than assumed.

If `cores/imxrt1176/imxrt1176.h` lacks defines for these three pads, add them there as register
facts with the `fsl_iomuxc.h` citation, matching how the camera work added its GPIO9/GPIO11 pads —
do not inline raw addresses in the driver.

 *
 * Copyright (c) 2026 Nicholas Newdigate
 * SPDX-License-Identifier: MIT
 *
 * Fact-source: mcuxsdk components/video/display/hx8394/fsl_hx8394.c
 * (BSD-3-Clause) -- HX8394_Init(), s_hx8394Cmds[] and the setmipi[] builder.
 * The register values and their ORDER are facts transcribed from that file;
 * the code around them is ours.  No GPL source is consulted for this panel.
 *
 * hx8394Init() must be called AFTER mipiDsiBegin(): the panel has no registers
 * in the SoC map and nothing to listen with until the DSI host is up.
 */
#pragma once
#include <Arduino.h>
#if defined(__IMXRT1176__)

// Run the full panel bring-up: power -> reset pulse -> SETEXTC unlock ->
// SETMIPI (carrying PANEL_DSI_LANES) -> the 21-command tuning table -> DCS
// sleep-out -> 120 ms -> DCS display-on -> backlight.
//
// Returns false at the first packet the DSI host refuses, leaving the backlight
// OFF -- lighting a panel that was not configured produces exactly the
// "backlit but blank" state that cost the RPi bring-up two sessions to
// diagnose, so this deliberately never gets there.
bool hx8394Init();

#else
#error "hx8394 targets the i.MX RT1176 (__IMXRT1176__)"
#endif

```cpp
/* hx8394.cpp - see hx8394.h for the fact-source and the ordering contract. */
#include "hx8394.h"
#include "panel_gpio.h"
#include "panel_config.h"
#include "mipi_dsi.h"
#if defined(__IMXRT1176__)

namespace {

// DSI data types (MIPI DSI spec; the same encodings fsl_mipi_dsi.h uses).
// MIPI_DSI_GenericWrite() in fsl_display.h picks the type from the payload
// length, which is what these three reproduce.
constexpr uint8_t DT_GENERIC_SHORT_WRITE_1 = 0x13;  // 1 byte  (opcode only)
constexpr uint8_t DT_GENERIC_SHORT_WRITE_2 = 0x23;  // 2 bytes (opcode + 1)
constexpr uint8_t DT_GENERIC_LONG_WRITE    = 0x29;  // 3+ bytes
constexpr uint8_t DT_DCS_SHORT_WRITE_0     = 0x05;  // DCS, no parameter

constexpr uint8_t DCS_EXIT_SLEEP_MODE = 0x11;
constexpr uint8_t DCS_SET_DISPLAY_ON  = 0x29;

// One generic write, typed by length exactly as MIPI_DSI_GenericWrite() does.
bool genericWrite(const uint8_t *cmd, uint32_t len) {
  const uint8_t dt = (len == 1u) ? DT_GENERIC_SHORT_WRITE_1
                   : (len == 2u) ? DT_GENERIC_SHORT_WRITE_2
                                 : DT_GENERIC_LONG_WRITE;
  return dsiWrite(0u, dt, cmd, len);
}

bool dcsWrite0(uint8_t cmd) {
  return dsiWrite(0u, DT_DCS_SHORT_WRITE_0, &cmd, 1u);
}

// The tuning table, transcribed VERBATIM from fsl_hx8394.c s_hx8394Cmds[].
// 21 entries.  The VALUES are panel-calibration data (gamma, power, gate
// timing) that cannot be derived or sanity-checked from outside the panel, and
// the ORDER is load-bearing: 0xBD is a page/bank select, so the four 0xBD
// writes and the two 0xB1 writes are NOT redundant -- each 0xB1 lands on the
// page the preceding 0xBD selected.  Do not reorder, dedupe or "tidy" this.
struct Cmd { const uint8_t *bytes; uint8_t len; };

const uint8_t c36[] = {0x36, 0x02};
const uint8_t cB1[] = {0xB1, 0x48, 0x12, 0x72, 0x09, 0x32, 0x54, 0x71, 0x71, 0x57, 0x47};

bool hx8394Init() {

  // Power-up and reset timing from HX8394_Init(): power high, 1 ms; reset low,
  // 1 ms; reset high, 50 ms.  The 50 ms is the panel's internal boot -- sending
  // SETEXTC early is silently ignored, which presents as a dead panel.
  panelPower(true);
  delay(1);
  panelReset(true);
  delay(1);
  panelReset(false);
  delay(50);

  // SETEXTC: the manufacturer-command unlock.  Everything below is ignored
  // until this lands, so it MUST be first.
  static const uint8_t setextc[] = {0xB9, 0xFF, 0x83, 0x94};
  if (!genericWrite(setextc, sizeof(setextc))) return false;

  // SETMIPI, with the lane count in the low bits of param0 -- fsl_hx8394.c
  // builds it as 0x60 | (dsiLanes - 1).  This value MUST agree with what
  // mipiDsiBegin() put in the host's CFG_NUM_LANES; a mismatch is silent on
  // silicon, which is exactly why the QEMU model cross-checks it.
  uint8_t setmipi[] = {0xBA, 0x60, 0x03, 0x68, 0x6B, 0xB2, 0xC0};
  setmipi[1] |= (uint8_t)(PANEL_DSI_LANES - 1u);
  if (!genericWrite(setmipi, sizeof(setmipi))) return false;

  for (const Cmd &c : kTable) {
    if (!genericWrite(c.bytes, c.len)) return false;
  }

  if (!dcsWrite0(DCS_EXIT_SLEEP_MODE)) return false;
  delay(120);                       // HX8394_Init()'s post-sleep-out wait
  if (!dcsWrite0(DCS_SET_DISPLAY_ON)) return false;

  // Backlight LAST, and only on success: see hx8394.h.
  panelBacklight(true);
  return true;
}
#endif

// Eight bars, chosen so adjacent ones differ in more than one channel -- a
// swapped or truncated colour channel then shows as a wrong bar rather than a
// subtly wrong shade.
constexpr uint16_t kBars[8] = {
  0xFFFF, // white
  0xFFE0, // yellow
  0x07FF, // cyan
  0x07E0, // green
  0xF81F, // magenta
  0xF800, // red
  0x001F, // blue
  0x0000, // black
};
}  // namespace

void DisplayClass::drawTestPattern() {
  _frame_ok = false;
  if (!_fb) return;

  const uint32_t barWidth = PANEL_WIDTH / 8u;
  for (uint32_t y = 0; y < PANEL_HEIGHT; y++) {
    uint16_t *row = _fb + (y * (PANEL_PITCH_BYTES / PANEL_BYTES_PER_PIXEL));
    for (uint32_t x = 0; x < PANEL_WIDTH; x++) {
      // Bar index saturates at 7 so a width that is not a multiple of 8 cannot
      // index off the end -- 720/8 is exact, but the guard survives a reuse.
      uint32_t bar = x / barWidth;
      if (bar > 7u) bar = 7u;
      row[x] = kBars[bar];
    }
    // The diagonal: one white pixel per row, sweeping left to right across the
    // full height.  Runs the other way if the image is flipped, which is the
    // point.
    const uint32_t dx = (uint32_t)(((uint64_t)y * PANEL_WIDTH) / PANEL_HEIGHT);
    row[dx] = 0xFFFF;
  }

  // The CM7 D-cache is off (startup.c), so there is nothing to clean between
  // these CPU writes and the LCDIFv2's AXI reads of the same buffer. Enabling
  // the D-cache later would make this a coherency problem.
  _frame_ok = waitScanoutFrame();
}
```

// 48.6.1.7). W1C: clear it, wait a frame, read it back -- a latch that returns
// means the output starved during that frame.
void DisplayClass::sampleUnderrun(uint32_t frames) {
  _underrun_frames = frames;
  _underrun_count = 0;
  for (uint32_t i = 0; i < frames; i++) {
    LCDIFV2_INT_STATUS(0) = LCDIFV2_INT_UNDERRUN;   // W1C
    if (!waitScanoutFrame()) break;                 // bounded; stops on a dead display
    if (LCDIFV2_INT_STATUS(0) & LCDIFV2_INT_UNDERRUN) _underrun_count++;
  }
}
