"-device usb-audio,bus=usbhost.0" cannot resolve and QEMU exits before the
firmware runs. This is the red the Phase 2 model change fixes; it is checked in

QEMU refuses the -device argument at startup because the mimxrt1060-evk
machine's OTG2 controller has no device id, so its EHCI host bus is never
named "usbhost.0" (unlike mimxrt1170-evk, where it is). QEMU exits before
loading the kernel image, no UART is ever opened, and the gate's own
gate_require_capture fails by name on the missing capture file -- exactly the
two-stage failure this task's design predicted.
