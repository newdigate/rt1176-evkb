★★ OBSERVER EFFECT -- READ THIS FIRST (2026-09-04).
The first bench run used the M2_BT_ACL_TRACE build and produced a PERIODIC
CRACKLE, not a tone.  It was the TRACE, not the stack: each 132-byte media
packet became a ~439-char console line (`acl_trace ... hex=<132 bytes>`), which
takes ~38 ms to print at 115200 baud, and CONSOLE.print BLOCKS when its TX
buffer fills.  That print runs inside L2cap's send loop, so it paced media to
11520/439 = ~26 packets/s -> the audio underran ~13x -> a ~26 Hz crackle.
Measured cadence between media packets: 38.95 ms (arithmetic: 439 chars /
11520 chars/s = 38.1 ms -- an exact match).  The SBC CONTENT was always correct
(the traced frames decode via ffmpeg to a clean 1 kHz sine, RMS 11588, est 1000
Hz).  Fix: the trace now SKIPS RTP media packets (payload 0x80 0x60); the
default build has no trace at all.  Lesson: a per-packet console dump at 115200
throttles any high-rate BT stream -- never trace media during A2DP.

★ RESIDUAL-DROPS FIX (2026-09-04).  The first clean-tone run held drops=0 for
~130 s then shed minor bursts (1.7%).  A diagnostic build (per-second rates +
min ACL credits) showed the cause: at ONE SBC frame per RTP packet we sent ~344
packets/s against a 7-credit ACL pool, so `credmin` ran to 0 and a brief link
stall (RF/sink backpressure) overflowed the ring.  Fix: `poll()` now batches --
it drains only once a full packet's frames are ready (or a short flush deadline),
so packets carry ~5 frames and the rate falls to ~69/s (5x less credit churn).
Result above: packet rate 344->69/s, ring high-water 7->5 steady, **drops=0 over
5+ minutes**, real-time throughout.  (A separate diagnostic run had also shown
the un-batched build hold drops=0 for 5 min under good RF -- the earlier drops
were a marginal-credit + RF transient, which batching removes the headroom
problem for.)

CLEAN TONE CONFIRMED AUDIBLE on the Shokz (bench, 2026-09-04).  blocks hold at
344/s (44100/128) -- real-time -- with drops=0 for the first ~130 s (the >=60 s
"no dropouts" acceptance is met).  After ~2 min the ring (64) occasionally fills
and sheds minor bursts (1546 drops / 89594 frames = 1.7% by n=260); audibly
clean per the listener, and a separate refinement (ring depth / batching / link)
rather than the crackle bug, which was the trace observer effect above.
