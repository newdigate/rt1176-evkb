BT-3 / NEW-9 headset A2DP: a 1 kHz tone streamed to a real Shokz "OpenMove by
Shokz" over SSP.  M2Radio eb1c8b5 (headset AVDTP DISCOVER fix: L2CAP MTU option
+ 5 channels; Avdtp GetAllCapabilities + SEP-walk + delay reporting +
DelayReport-accept; Sdp server; BtLink paging + credit-reclaim + disconnect).

★★ OBSERVER EFFECT -- READ THIS FIRST (2026-09-04).
The first bench run used the M2_BT_ACL_TRACE build and produced a PERIODIC
CRACKLE, not a tone.  It was the TRACE, not the stack: each 132-byte media
packet became a ~439-char console line (`acl_trace ... hex=<132 bytes>`), which
takes ~38 ms to print at 115200 baud, and CONSOLE.print BLOCKS when its TX
buffer fills.  That print runs inside L2cap's send loop, so it paced media to
11520/439 = ~26 packets/s -> the audio underran ~13x -> a ~26 Hz crackle.
Measured cadence between media packets: 38.95 ms (arithmetic: 439 chars /
11520 chars/s = 38.1 ms -- an exact match).  The SBC CONTENT was always correct
(the traced frames decode via ffmpeg to a clean 1 kHz sine, RMS 11588, est 1000
Hz).  Fix: the trace now SKIPS RTP media packets (payload 0x80 0x60); the
default build has no trace at all.  Lesson: a per-packet console dump at 115200
throttles any high-rate BT stream -- never trace media during A2DP.
