synthui_knob_test -- HARDWARE (MIMXRT1170-EVKB + RK055), synthui_rotary_knob
================================================================================
2026-08-27, NEW-20 Phase 2. Same ELF the QEMU gate runs (build/, VGLITE-flavor
SynthUI, LVGL software renderer). On silicon the chip-ID probe finds the GC355
and the widget's compositor attaches, so every checksummed screen is rendered
well-by-LVGL-sw + rotor-by-GC355 (cached vg_lite paths, RENDER_READY pass).

THE GPU GOLDEN SET -- silicon-only, never reconciled with the gate's sw set
(hardware AA is not LVGL mask arithmetic; vglite_lvgl_test's precedent).
Reproduced BIT-IDENTICALLY across three boots the same session (two before a
reflash, one after):

  RK_CHIP_ID=0x00000355
  rk_engine=gpu
  LVGL_FLUSHED=PASS
  LVGL_BYTES=3686400
  KNOB_SUM_ALL=0x90CFC433
  KNOB_SUM_ENDLESS_LIGHT=0xBF3D3E5C
  KNOB_SUM_BOUNDED_LIGHT=0xCFCB3D95
  KNOB_SUM_ENDLESS_DARK=0xBD3C8A9D
  KNOB_SUM_BOUNDED_DARK=0xFB46F107
  KNOB_SUM_ACCENT=0x2C1D9DCD
  rk_gpu_err=0
  SYNTHUI_KNOB_DONE

rk_gpu_err=0 is load-bearing: a rejected vg_lite draw paints nothing and the
sums would still be perfectly stable (stable pictures of a missing rotor), so
the counter is what says the GC355 actually executed every draw.

THE FRAME WAS LOOKED AT, coherently: the live hero screen tears under an SWD
dump (the animation repaints while the probe reads -- expected, the same
direct-to-scanout behavior the bench documented), so the grid was inspected
via the RK_EYEBALL_HOLD=1 diagnostic build (see CMakeLists.txt): it printed
the SAME KNOB_SUM_ALL=0x90CFC433 and held, tools/rt1170-screenshot.py then
dumped a static frame whose own FNV-1a equals that sum. The eye checked:
GC355-composited rotors seated inside the sw-painted wells in all 16 cells,
light/dark palettes, yellow dark-theme index wedges and focus rings, muted
disabled column, per-column angles -105/-35/+35/+105, and at 3x zoom clean
hardware-AA rotor edges with NO dark fringes (the premultiply check from the
bench spec section 6 -- sw-premultiplied + SRC_OVER is correct; here the
rotor path is fills-only, and the check still applies to AA edge blending).
797 distinct colours in the frame vs the software renderer's far coarser
count -- the visible signature of hardware AA, and the reason the two golden
sets can never be reconciled.

Console: MCU-Link VCOM (/dev/cu.usbmodem5DQ2DDHVWO5EI3) via
tools/rt1170-console.py. Flash: LinkServer 26.6.137, flash load -> verify
(VCOM free) -> attach reader -> reset via backgrounded `LinkServer run`,
per the standing bench order. (The board was subsequently reflashed to
acid_box for its own silicon check the same session.)
