★★ ANALYSIS — the P2 decision input
-----------------------------------

1. THE CPU FULL-SCREEN SYNC COPY COSTS 89.5 ms — 2.7x THE ENTIRE 33 ms FRAME
   BUDGET.  Non-cacheable SDRAM memcpy runs at ~20 MB/s effective; the PXP
   does the same copy in 12.3 ms (~150 MB/s), a 7.3x win.  Any full-screen
   invalidation (screen transition, theme change) on the double-buffered path
   currently pays the CPU number every frame it happens.

2. PXP WINS 13 OF 14 CASES, from 5.4x to 21x.  The realistic button-press
   sync (case 5, 120x140) is 1.79 ms CPU vs 0.23 ms PXP.

3. THE ONE CPU WIN IS THE SINGLE-ROW CASE (10: 719x1 — 70 us vs 105 us).
   The discriminator is NOT area: case 1 (256 px over 16 ROWS) wins 21x on
   the PXP while case 10 (719 px in ONE row) loses.  The CPU's row-loop is
   fast on one contiguous row and slow on many small rows; the PXP's cost is
   near-flat per operation.  THE HONEST THRESHOLD IS HEIGHT >= 2 ROWS, not a
   pixel-area floor.

4. Case 11 (1x1280 — 1280 rows of one pixel) still wins 2x on the PXP,
   consistent with (3).

Crossover, stated for the handler: accelerate when the copy spans >= 2 rows;
single-row copies stay on the CPU default.  (The install API's threshold_px
remains as a belt-and-braces floor; the height check is the load-bearing one
and cites this transcript.)
