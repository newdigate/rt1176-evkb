★★ RESOLVED AMBIGUITIES — the measured verdicts on the RM's contradictions
--------------------------------------------------------------------------
Measured across six instrumented runs (DIAG pixel triples, a 256-point
alpha-gradient sweep, and two 256-point MULTIPLY sweeps at Ga=0x80/0xC3):

1. BLEND DIRECTION (RM 52.3.1.12 prose vs its own equation): the PROSE is
   correct — alpha weights the AS (a=0 -> PS passes, a=0xFF -> AS passes).
   The RM's equation, which weights PS, is the typo.

2. BLEND ARITHMETIC: out = (a*AS + (256-a)*PS) >> 8 — plain a, divisor 256,
   TRUNCATING — with EXACT AS pass-through at a==0xFF (the RM's "will not be
   blended" sentence is literal).  Fit 256/256 gradient points; /255-rounded
   fit 196/256; a+(a>>7)-mapped fit 238/256.  The pass-through special case
   was exposed by the opaque-565 and AS-key cases (their GOTs are byte-exact
   pure AS, which the /256 leak cannot produce).

3. EFFECTIVE ALPHA PER MODE: EMBEDDED -> Ea; OVERRIDE -> Ga;
   MULTIPLY -> (Ga*Ea + 128) >> 8 (round-nearest /256; fit 512/512 across two
   global alphas — the RM's (Ga*Ea+0x80)/128 cap-128 text fit 14/512);
   INVERT -> applied last as 255-a.

4. AS-KEY RESULT (AS_CTRL field description vs RM 52.3.1.13): the FIELD
   DESCRIPTION is correct — an AS-key hit makes the overlay pixel transparent
   (PS shows).  52.3.1.13's "AS is passed" is the typo.  PS-key hit -> AS
   passes UNBLENDED (verified byte-exact); both-keys hit -> PS_BACKGROUND.
   All 12 ROPs match the RM table as transcribed, first try, both runs.

5. OUTPUT X BYTE with the legacy engine ARMED (XRGB8888 OUT): a NONZERO
   per-pixel computed alpha, fully deterministic (identical dump in every
   run).  The analytic formula was deliberately not derived: no consumer
   reads the byte.  The QEMU model does NOT claim it and the gate checks the
   ALPHA_OUT line's presence only — a stated asymmetry, like UNDERRUN vacuity.
