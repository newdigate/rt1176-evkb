m2_lwip_test -- hardware verification on the real MIMXRT1170-EVKB RevC3
========================================================================
Date: 2026-08-19.  Card: u-blox M2-MAYA-W161 (IW416/SD8978) in J54, antenna
fixed in W8.  Driver: M2Radio @ the W9 ring/serviceLink/netif commits.
Oracle: ESP8266 SoftAP "ESP8266TEST", WPA2-PSK, ch6, 192.168.4.1, running
the session sketch (1 Hz UDP broadcast to :4711, WiFiServer TCP echo on
:4712, station-event + echo logging on its own serial port).  Dual serial
capture on one timeline (EVKB MCU-Link VCOM + ESP CP2102).

VERDICT: PASS.  lwip's own DHCP client bound in ~3 s and the raw-API TCP
echo client ran the whole 3-minute window CLEAN: 86 connects, 86 byte-exact
echoes, 0 failures, 0 reconnects, RX rings healthy throughout.

Notes:

* The echo payload is "M2LWIP hello <n>" with a per-attempt counter, and the
  client verifies the echo BYTE-EXACT (pbuf_memcmp) before counting ok -- an
  ESP-side fabrication or truncation would count as fail, and none did.
* ring=T/R/n cycles through the full 32-port SDIO rings with resyncs
  pinned at 0 -- the W8 ring model holding at ~4 pkt/s TCP + 1 Hz broadcast.
* Found during this bring-up: the example initially OMITTED the M.2 board
  preamble (SDIO_RST/WL_RST release + 1.8 V pad switch, m2_sdio_probe's
  W2/W3 work) and fell to the device-absent fallback on silicon while its
  QEMU gate stayed green -- QEMU has no card either way, so it CANNOT see
  this class of omission.  The preamble now lives at the top of setup()
  with a comment carrying the lesson.  "QEMU pass is necessary, never
  sufficient", instance N+1.
* The firmware idle RX-death erratum (sparse traffic, IEEE PS off, dies
  stochastically at ~14-44 min -- see the W8/W9 soak record in
  m2_sdio_probe's transcript and the W10 handoff) is NOT hit inside this
  3-minute window; at this example's ~5 pkt/s it also sits above the
  observed sparse-traffic trigger regime.  The PS-enable workaround is W10
  driver work.
