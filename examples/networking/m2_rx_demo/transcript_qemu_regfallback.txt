W16: the assumption that fails LOOKING HEALTHY, and the check that catches it
------------------------------------------------------------------------------
Date: 2026-08-20.  Driver M2Radio b44877c, model qemu2 7e17eff5d3.
Gate: run_qemu_regfallback.sh.

W16's register-port read follows NXP's driver exactly, including holding the
CMD53 address FIXED (OP Code 0).  For an ordinary SDIO function that means
"read one register 196 times".  We believe this card streams the register file
instead -- NXP's driver plainly depends on it -- but no capture in this tree
proves it, and there is no way to tell from the outside.

Run against `reg-port-literal=on`, the model's implementation of the other
reading (its NOTE 16), with the driver's CARD_STATUS check in place:

    demo_done frames=8 rx_data=8 rd_bitmap=0x0 ... c52svc=52240 c53regs=1/0
              c53rx=1 rxaggr=1/8 mpregs=0 rej=0x0 mperr=0 split=0

  mpregs=0    the check fired: the snapshot's CARD_STATUS byte did not match
              the one begin() had already read by CMD52.  Two TRANSPORTS
              compared against each other, not against a constant the driver
              invented.
  rej=0x0     what came back instead -- register 0 (HOST_POWER_UP), 196 times.
  c53regs=1/0 exactly one register-port read ever happened; the port is
              abandoned for the firmware's life, not retried per pass.
  c52svc=52k  the cost of the fallback, and the reason it is visible in a soak
              rather than silent.
  rxaggr=1/8  RX aggregation STILL WORKED -- the fallback fills the same
              snapshot struct by CMD52, so only the transport degrades.

AND WITHOUT THE CHECK.  Same model, same image, sanity check disabled:

    tx=cmd-timeout wr_bitmap=0x0 tx_port_now=0
    demo_done frames=0 rx_data=0 rd_bitmap=0xFF wr_bitmap=0x0 ring=0/0/0
              stranded=0/0 drainerr=0 notready=0 int_seen=0xC2 tx=0 c53=0
              c53regs=7676/204 c53rx=0 rxaggr=0/0 mpregs=1

Read that line, because it is the whole argument.  RX dead, TX dead, and EVERY
HEALTH COUNTER CLEAN: stranded=0/0, drainerr=0, notready=0, ring never moved.
An all-zero register snapshot is byte-identical to a healthy idle card, so
nothing in the driver has anything to complain about.  The one contradiction
in the line is rd_bitmap=0xFF -- eight uploads waiting -- and that value comes
from probeRdBitmap(), which reads the bitmap by CMD52 and therefore saw the
truth the register port was hiding.  A bench session would have had that
single byte to go on.
